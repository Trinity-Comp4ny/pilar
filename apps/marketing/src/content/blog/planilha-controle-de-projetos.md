Uma planilha de controle de projetos para escritório de engenharia ou arquitetura precisa de uma linha por disciplina de cada projeto, não uma linha por projeto. As colunas essenciais são: projeto, cliente, etapa, disciplina, responsável, data de início, previsão de entrega, status, aguardando o quê, data da última atualização e parcela ligada à entrega. Com essas colunas e uma pessoa dona da planilha, ela funciona bem enquanto o escritório tem poucos projetos e pouca gente.

O problema não é a planilha em si. É que ela não avisa ninguém, não guarda o histórico e depende de alguém lembrar de atualizar. Abaixo, o modelo de colunas, as regras para mantê-la confiável e os sinais de que ela deixou de servir.

## Modelo de colunas para a planilha de controle de projetos

A decisão mais importante é a granularidade. Uma linha por projeto esconde o que importa: o projeto está "em andamento", mas a estrutura está parada esperando sondagem e ninguém vê. Uma linha por disciplina mostra onde está o gargalo.

| Coluna              | O que preencher                            | Exemplo                              |
| ------------------- | ------------------------------------------ | ------------------------------------ |
| Projeto             | Nome curto e único                         | Residência Alves                     |
| Cliente             | Quem contratou                             | Família Alves                        |
| Etapa               | Fase do projeto                            | Executivo                            |
| Disciplina          | Uma por linha                              | Estrutural                           |
| Responsável         | Uma pessoa, com nome                       | Carla                                |
| Início              | Data em que a disciplina começou           | 03/03                                |
| Previsão de entrega | Data combinada                             | 28/03                                |
| Status              | Lista fechada de opções                    | Em andamento                         |
| Aguardando          | O que trava e de quem                      | Sondagem do cliente                  |
| Última atualização  | Quando alguém mexeu na linha               | 17/03                                |
| Parcela ligada      | Parcela do contrato que depende da entrega | Parcela 3                            |
| Observação          | Uma frase, não um diário                   | Cliente pediu revisão de vão na sala |

### Status com lista fechada

Defina de quatro a seis status e trave a coluna com validação de dados. Por exemplo: não iniciado, em andamento, aguardando, em revisão, entregue. Se cada pessoa escreve o status do seu jeito ("quase pronto", "falta pouco", "ok?"), filtrar a planilha vira adivinhação.

### A coluna que mais falta: aguardando

A maior parte dos atrasos em projeto multidisciplinar não vem de alguém trabalhando devagar, mas de uma disciplina parada esperando insumo. A coluna "aguardando" transforma a planilha de registro em ferramenta de cobrança: filtre por ela toda segunda-feira e você sabe quem precisa ser cobrado, inclusive o cliente.

## Regras para a planilha não virar bagunça

Planilha sem regra apodrece em semanas. As que mais ajudam:

1. **Um dono.** Uma pessoa é responsável por manter a planilha. Todos podem atualizar a própria linha, mas alguém confere.
2. **Atualização com data fixa.** Toda segunda, antes da reunião de equipe. Linha com "última atualização" velha é linha suspeita.
3. **Nunca apagar linha.** Disciplina entregue muda de status; projeto encerrado vai para outra aba. Histórico apagado não volta.
4. **Mudança de prazo com motivo.** Crie uma aba de histórico ou uma coluna de "data original". Sem isso, ninguém sabe se o projeto atrasou ou se a data foi mudada três vezes.
5. **Um arquivo só.** Cópia local, versão "final2" e anexo de e-mail são o começo do fim.
6. **Sem cálculo escondido.** Fórmula que ninguém entende vira fórmula que ninguém corrige.

## Quando a planilha de controle de projetos deixa de servir

Não existe um número exato de projetos a partir do qual a planilha quebra. O sinal é de comportamento. Se três ou mais itens abaixo descrevem o seu escritório, a planilha já está custando mais do que economiza.

- **Ninguém confia no que está lá.** Antes de responder ao cliente, alguém pergunta para a pessoa em vez de olhar a planilha.
- **A reunião de segunda serve para atualizar a planilha,** não para decidir nada.
- **A passagem de bastão depende de memória.** A arquitetura fechou e o projetista de estruturas descobre dias depois.
- **O histórico de prazo some.** Na conversa difícil com o cliente, ninguém consegue mostrar quando e por que a data mudou.
- **A carteira não cabe numa tela.** Para saber quem está sobrecarregado, alguém monta um gráfico à parte.
- **O financeiro vive em outra planilha.** Para saber se a parcela da entrega foi paga, é preciso cruzar dois arquivos.
- **O cliente pede status e alguém monta um resumo à mão,** toda vez.

Cada um desses itens tem a mesma origem: a planilha guarda dados, mas não age sobre eles. Ela não avisa a próxima disciplina, não exige motivo para mudar data, não junta prazo e dinheiro e não mostra nada ao cliente sem alguém exportar. A comparação completa está em [planilha contra sistema](/vs/planilha).

## Planilha, quadro de tarefas ou sistema de gestão?

O caminho natural de muitos escritórios é sair da planilha para um quadro de tarefas genérico. Ele resolve a visualização, mas costuma tratar o projeto como uma lista de cartões, sem disciplina, dependência ou contrato. Vale ler a comparação com o [Trello](/vs/trello) antes de decidir.

Um sistema feito para escritório de projeto parte de outro desenho: o projeto é um conjunto de disciplinas, cada uma com responsável e data, ligado ao contrato e às parcelas. O que a planilha pede que alguém lembre, o sistema faz por regra. Para entender o que avaliar, veja [software de gestão para escritório de engenharia](/blog/software-gestao-escritorio-engenharia).

### Como sair da planilha sem parar o escritório

1. **Não migre o passado.** Cadastre os projetos ativos e deixe os encerrados na planilha, como arquivo.
2. **Defina o fluxo padrão antes.** Quais etapas e disciplinas a maioria dos projetos segue, e quem responde por cada uma.
3. **Escolha uma data de virada.** A partir dela, a reunião de segunda usa só o sistema.
4. **Desligue a planilha.** Se as duas continuam vivas, a equipe atualiza a mais fácil e as duas ficam erradas.

## Perguntas frequentes

### Quais colunas uma planilha de controle de projetos deve ter?

No mínimo: projeto, cliente, etapa, disciplina, responsável, início, previsão de entrega, status, aguardando, última atualização e parcela ligada. Use uma linha por disciplina, não por projeto, para enxergar onde está o gargalo.

### Planilha de controle de projetos serve para escritório pequeno?

Serve bem no começo, com poucos projetos e uma pessoa dona da planilha. O sinal de troca não é o tamanho, mas o comportamento: quando ninguém confia nos dados e a reunião vira sessão de atualização.

### Como controlar mudança de prazo na planilha?

Mantenha uma coluna com a data original e uma aba de histórico com data, disciplina, novo prazo e motivo. Sem isso, a conversa com o cliente sobre atraso vira versão contra versão.

### Dá para migrar da planilha para um sistema sem parar o trabalho?

Dá. Cadastre só os projetos ativos, defina o fluxo padrão, marque uma data de virada e desligue a planilha depois dela. Os projetos encerrados podem continuar no arquivo antigo.
