## TL;DR
Tese clássica de 2011: software está "comendo" indústria após indústria — empresas de software
de alta margem e defensáveis substituem incumbentes em varejo, mídia, finanças, recrutamento etc.
Maturação de banda larga/cloud/mobile + custo de startup despencando tornam viável atacar setores
antes "imunes". É a base intelectual do atual "AI is eating software": mesma lógica, próxima camada.

## Pontos-chave
- **Software como força horizontal de disrupção:** todo setor é candidato; quem não virar empresa de software perde para quem virou.
- **Negócios de software são reais, não bolha:** alta margem, alto crescimento, **altamente defensáveis** — não especulação.
- **Exemplos canônicos:** Amazon vs Borders, Netflix vs Blockbuster, Square/PayPal em pagamentos, LinkedIn em recrutamento, iTunes/Spotify em música, Pixar em animação.
- **Habilitadores:** banda larga + cloud + mobile maduros e custo de fundar despencando → setores antes "resistentes" agora atacáveis.
- **Setores ainda na fila (em 2011):** saúde, educação, agricultura, defesa, óleo/gás — previsão que se confirmou.

## Frameworks / números
- Sem benchmarks numéricos no ensaio (é tese, não relatório).
- Critério qualitativo de negócio "bom": **alto crescimento + alta margem + altamente defensável**.
- Horizonte da previsão: 10 anos (2011→2021) de disrupção setor a setor — confirmada.

## Aplicação ao Pilar
- **AEC é um dos "setores na fila"** que software (e agora IA) só agora torna economicamente atacável — exatamente a janela que o ensaio descreve, uma camada acima.
- **Defensibilidade é o teste central:** Pilar precisa ser "highly defensible", não só útil. O moat não é o software de orçamento em si, é o dado proprietário de projetos AEC acumulado.
- **Narrativa de fundraising:** ancorar o pitch em "AI is eating software, software já comeu o resto" — Pilar é o agente que come o trabalho do escritório de engenharia, não mais um SaaS de registro.
- **Disciplina de margem:** o ensaio define negócio bom por margem alta; cuidado com agentes que viram repasse de custo de inferência (margem baixa) — preço por resultado, não por token.
