## TL;DR
a16z: "computer use" (o agente operar a interface gráfica como um humano, sem depender de API) destrava agentes que executam workflows digitais ponta-a-ponta — não ferramentas de uso único. Mas o ponto-chave pro Pilar: um agente treinado só em software genérico NÃO navega ambientes enterprise complexos out-of-the-box; quem vence é quem domina verticalização + contextualização. Genérico (Claude puro) não conhece os padrões do escritório. O valor migra pra atingimento de objetivo (outcome), e o moat é profundidade de contexto de domínio.

## Pontos-chave
- Agente ponta-a-ponta > ferramenta de uso único: localizar doc no banco → extrair dado → atualizar sistema X → notificar no Slack → gerar relatório, sem humano no meio.
- Efeito multiplicativo: o potencial emerge da interação entre acessibilidade de ferramenta (qualquer GUI) × capacidade de raciocínio.
- Computer use resolve o "long tail" de software sem API — exatamente onde o trabalho enterprise real vive (sistemas legados, portais).
- Imperativo da verticalização: "improvável que um agente treinado só em software genérico navegue ambientes enterprise complexos out-of-the-box" — precisa de contexto significativo, como os chatbots/assistentes enterprise que vieram antes.
- Quem ganha = startups que dominam verticalização e estratégias de contextualização, NÃO os provedores de modelo genérico.
- Funções de serviço colapsam em papéis operados por agente: coordenador de compliance, scheduler de projeto, processador de licença — viram capacidades que o agente "possui" ponta-a-ponta.
- Valor migra upstream: o agente otimiza objetivo estratégico (ex: atingir X dentro do orçamento), não tarefas discretas → pricing tende a outcome, moat = profundidade de contexto + integração.

## Frameworks / números
- Equação: potencial do agente = acessibilidade de ferramenta × capacidade de raciocínio.
- Sem benchmarks numéricos; é ensaio de tese (capacidade técnica + verticalização).
- Distinção: provedor de modelo genérico (commodity) vs startup que verticaliza/contextualiza (defensável).

## Citações
> "It is unlikely that a computer-using agent trained solely on general software... will be able to navigate complex enterprise software environments out-of-the-box."
> "Computer-using models will require meaningful context, similar to the enterprise chatbots and assistants that preceded them."

## Aplicação ao Pilar
- Resposta direta ao medo "e se o ChatGPT/Claude fizer isso sozinho?": não faz — o a16z diz que o modelo genérico não navega o domínio AEC out-of-the-box. O moat do Pilar é o contexto do escritório (escopos, aditivos, custos por disciplina, padrões de margem), não o modelo. Usar isso no pitch defensivo e no positioning.
- O moat é profundidade de contexto + integração: quanto mais o Pilar conhece como aquele escritório orça/precifica/aprova, menos substituível por um agente genérico. Reforça instrumentar a memória por escritório (ver Bessemer).
- "Funções de serviço colapsam em papéis de agente": no AEC, orçar + montar proposta + acompanhar aprovação + alertar sobre margem em risco colapsam num agente — desenhar o roadmap nessa direção (não 1 feature isolada, mas o papel).
- Computer use como horizonte (não MVP): o long-tail sem API (portais de prefeitura, sistemas legados do cliente) é onde computer use brilha — anotar como expansão futura, mas o wedge atual (orçamento) já vive dentro do dado do próprio Pilar, sem precisar disso.
- Pricing por objetivo atingido reforça o value metric "por orçamento/proposta aprovada" — não por assento.
